# Как обучались три финальные модели

Пути ниже — относительно корня репозитория. В архиве сдачи те же файлы лежат внутри `training/` с такими же путями. Подробный разбор с SHA всех промежуточных состояний — в `work/notes/training-lineage.md`.

## Схема

```
данные: 9 725 737 пар · compact-представление кода · свой BPE на 8195 токенов
                                   │
W:   B2 (с нуля) → B3 → B4 → B5 ───────→ B7: охлаждение 33 000 шагов ─────────→ W B7
C:   L1 (с нуля) → L2 (long2x) → L3 ─┬─→ B5 → B7: охлаждение 65 800 шагов ───→ C-long2x B7
                                     └─→ P1: охлаждение 31 372 шага + усечение → P1-B
```

- Каждая стрелка — продолжение из **полного состояния**: веса FP32, моменты AdamW, GradScaler, состояния генераторов случайных чисел и позиция в порядке данных. Warmup после продолжения не повторяется.
- Основная фаза идёт с постоянным LR. Промежуточные охлаждения внутри L1–L3 и B2–B5 — только пробы для оценки: после замера восстанавливалось состояние до охлаждения, и дальше обучение шло без них.
- Настоящее охлаждение — только последний шаг (B7 и P1).
- **B7 не продолжает B6:** оба заново стартуют из одних и тех же неохлаждённых состояний B5. **P1-B не предок C B7:** P1 и B5 независимо стартуют из одного состояния L3.

## Общий рецепт

- **Архитектура:** Pre-LN encoder–decoder 6+6, SwiGLU, обучаемые позиции (2048), общий эмбеддинг encoder/decoder, отдельная выходная голова, dropout 0. Эмбеддинги инициализируются делёнными на $\sqrt{d}$, в forward умножаются обратно.
- **Оптимизация:** AdamW (weight decay 0,01), клиппинг градиента 1,0, FP16 с GradScaler (init 1024), эффективный батч 128 пар.
- **Лосс:** CE нормируется на число целевых токенов батча; EOS учитывается, PAD и BOS — нет.
- **Окружение продолжений:** Torch 2.11.0+cu128, CUDA 12.8, T4.
- **Шаги:** «updates» — это попытки шагов, включая пропуски GradScaler.

| Модель | Размер | Особенности |
|---|---|---|
| W | d768, 12 голов, SwiGLU 2048, 113,4 млн параметров | QK-LayerNorm по головам во всех attention; CE + z-loss $10^{-4}$; LR 0,0006, warmup 2000 |
| C | d512, 8 голов, SwiGLU 1368, 53,6 млн параметров | обычная CE; LR 0,0015, warmup 1000 |

## P1-B

Те же L1 → L2 → L3, что у C, затем отдельный запуск **P1** на аккаунте друга (`work/kaggle/notebooks/nlp-hw02-kaggle-p1.ipynb`, ветка B):

- Старт снова из неохлаждённого состояния L3, без основной фазы.
- Охлаждение 31 372 шага: $\mathrm{LR}_j = 0{,}0015\,(1-\sqrt{j/31372})$.
- **Стратифицированное усечение лосса:** в каждом батче из 128 пар отбрасываются 13 примеров с самой большой CE, с квотами по корзинам длины (границы 53/79/105 токенов). CE оставшихся усредняется по токенам.
- В том же ноутбуке сначала шла ветка A (то же охлаждение без усечения). Перед веткой B состояние L3 восстанавливалось полностью, так что A на B не влияет.

Итоговый файл: `p1-b-fp16.pt`, SHA-256 `84390377…db464a5`. При упаковке все три файла только переименованы, веса не менялись.

## Какие файлы что делают

- **Ноутбуки запусков** (`work/kaggle/notebooks/`, 9 штук: L1, L2, L3, P1, B2, B3, B4, B5, B7) — точное содержимое Kaggle-запусков. Каждый ноутбук несёт внутри исходники всех модулей (`SOURCES`), с которыми он реально работал, и проверяет их SHA.
- **Модули** (`work/kaggle/src/*.py`, `work/kaggle/*_worker.py`, `work/kaggle/legacy-c/`):
  - `*_runtime.py`, `*_worker.py` — цикл обучения и процессы на каждой GPU;
  - `*_resume.py`, `*_state.py` — сохранение и восстановление полного состояния;
  - `b2_optim.py`, `p1_math.py`, `b4_math.py` — оптимизатор, z-loss, расписание и усечение;
  - `qk_attention.py` — QK-нормировка;
  - `l1_cache.py`, `l2_sampler.py`, `b1_data.py` — данные и порядки;
  - `exp26_*`, `exp27*` — общее ядро модели, оценка и исполнение;
  - `session_*`, `*_live.py`, `kaggle_*` — оркестрация Kaggle: таймеры сессий, сохранение промежуточных состояний, проверки. Градиентов они не добавляют.
  - Для C используется старое ядро из `legacy-c/`, а не общий `src/exp26_core.py`, расширенный под W.
- **Чистая версия:** `submission/code/hw2_codegen/train.py` — та же математика шага в одном скрипте: рецепт C/P1, расписание с охлаждением, усечение, полное сохранение и продолжение. Это не исторический оркестратор; CPU-тесты подтверждают математику шагов, а не повтор многочасового обучения.

## Что важно для воспроизведения

- **С нуля:** публичный датасет (revision `b2724689…`) → токенизатор и выборки (19, 24) → кеш 26a + 26c → compact и проверенный кеш → порядки данных → запуски по таблицам. Старые модели этапа 1, B1, R1 и B6 для этого не нужны.
- **Время:** основная фаза в исторических запусках ограничивалась временем сессии. Поэтому для повтора именно этой траектории ориентируйтесь на записанные числа шагов и позиции курсора.
- **Версии модулей:** файлы в `src/` — последние версии. Для точного повтора раннего запуска берите исходники, встроенные в его ноутбук.

## Что не подтверждено файлами

- Скрипт, которым собраны исходные стартовые ZIP (защищённые вопросы и фиксированные входы оценки), в репозитории не найден. Сами ZIP, данные и полные чекпоинты в Git не входят.
- Номера версий Kaggle-ноутбуков L1 и L3, в которых шло обучение, не установлены. Состояния привязаны по SHA опубликованных промежуточных чекпоинтов.
- Для B5 отмена версий 1–5 известна с моих слов. Финальные веса B5 происходят из версии 6, которая стартует из исходных состояний B4 и L3.
