## Решение и границы

Три лучшие primary-альтернативы: k32g0 (+4,590 п.п.), k32g1 (+4,565) и k16g0 (+4,126). Все превышают 120 с: **493,33 / 499,75 / 309,53**. Порог качества ≥1,5 п.п. выполнен, порог времени — нет; **greedy по правилу**.

Это решение ограниченного top3-поиска: k4/k8 дают ≥1,5 п.п., но их test-время **не измерялось**. Из результата нельзя вывести, что любое голосование не укладывается в 120 с.

CE весов не менялась: 0,314924 / 0,331018. Лучший k32g0 по reference-длинам primary: 1627/2013 (<60), 848/1457 (60–90), 209/488 (90–120), 42/138 (≥120). Средние длины выбранных программ и все bins каждой конфигурации сохранены в JSON.

CPU повторил исполнение всех сохранённых кандидатов, кластеризацию `isclose`, выбор по голосам и tie-break greedy→mean logprob. Совпали status/value во всех пяти grids, все 50 scores и match sets, а также представители трёх test-наборов. Выбор не использует gold test.

## Ресурсы и ограничения

Весь №27: **3368,17 с = 56,14 мин**. Heldout4k: 266240 candidates, generation 1600,53 с, execution 75,13 с. Old1024: 66560 candidates, 339,07 / 13,36 с. Peak reserved **15474884608 байт = 14,412 GiB**.

В primary execution: 3 chunk retries / 2 pool restarts. Итог сохранён полностью, точное число повторных program calls неизвестно. Флаги SDPA включены; фактически выбранный backend и GPU utilisation не записаны.

> [!warning] Граница greedy-таймера
> Greedy в №27 измерен как generation + answers **без execution** (`executed_candidates=0`), хотя общая подпись таймера перечисляет execution. Если буквально требовать включения exec даже для greedy, этот замер неполон. Три sampling-альтернативы включают execution/voting/I/O и превышают 120 с.

Один seed, повторный выбор по heldout; fresh и официальный score не оценены. Полные CUDA-генерации при CPU-разборе не повторялись.
