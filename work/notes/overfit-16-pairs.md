## Гипотеза и условия

Прежняя модель должна запомнить 16 разных вопросов с программами из своего train. Если не получается, сначала исследовать подготовку и обучение; если получается — проверить расширение данных. Запоминание не оценивает обобщение или функциональную правильность исходных программ.

Первые 16 различных вопросов из прежнего пула 512 пар первого shard, тот же hash split и фильтр длин. Исходные программы не меняются. SHA-256 выбранных 16 пар: `d09cd3121ebfaac0707b52136008a00f6389fed0b3eec3b4a1c502e739bdeb6b`; длины программ с EOS 136–498 токенов, все помещаются в cap 512.

Полная конфигурация 2+2/128 и 1 254 915 параметров, 4 головы, FFN 512, ReLU, Post-LN, dropout 0.1, обучаемые позиции, байты, FP32. Seed 42, batch 8, AdamW LR 0.001 / weight decay 0.01, clipping 1.0. Исходный выполненный опыт: инициализация с нуля, бюджет 1000 шагов. Продолжение выполнено в новом присланном T4-прогоне: остановка на 2250 при точных 16/16 с EOS; лимит 3000 не исчерпан.

## Проверка успеха

Для $n=16$ пар:

$$
m=\frac{1}{n}\sum_{i=1}^{n}\mathbf{1}[\hat y_i=y_i].
$$

$y_i$ — исходные токены программы плюс EOS; $\hat y_i$ — greedy-токены модели без PAD, включая выданный EOS; $\mathbf{1}$ — индикатор равенства всей последовательности. При $m=1$ обучение останавливается. Совпадение декодированного текста без EOS само по себе не засчитывается.

- Шаг 0, затем шаг 1 и каждые 50: teacher-forcing loss на всех 16, точность непустых целевых токенов с EOS, число полностью правильных teacher-forced последовательностей и точность EOS. PAD исключён из loss и accuracy. Dropout выключен для проверки.
- Каждые 250 шагов и в конце: greedy всех 16, точное совпадение текста / токенов с EOS, первое расхождение, длины, EOS и AST. Префикс здесь собственный, а не исходный.
- После каждого логирования: JSON и соответствующий checkpoint. В последней ячейке печатаются первые 3 неудачи, при полном успехе — первые 3 совпадения.

Результат 16/16 — практический критерий этой диагностики, не доказательство корректности всех масок. Плохое запоминание также само по себе не доказывает ошибку или недостаток ёмкости. При частичном успехе изучить динамику и случаи, затем выбрать дополнительную длительность либо отдельный опыт LR/подготовки.

## Первый сохранённый результат: 1000 шагов

Tesla T4 / PyTorch 2.11.0+cu130, полная прежняя модель. 1000 шагов; общее время ячейки с диагностикой и записью checkpoint — 44.75 с, не чистое время обучения. Исходный файл `baseline_first_try_overfit16pairs_results.ipynb`, SHA-256 `4400ca9ae7c3eb910d13b58f7fb86c98d0b6666993f97b87c18b572f59218108`. Все 7 кодовых ячеек совпадают с подготовленным опытом; порядок 1–7, ошибок в outputs нет. Код и outputs сохранены, служебные метаданные Colab убраны.

| Шаг | Eval loss на 16 | Точность токенов | Greedy exact с EOS | Greedy EOS |
| --- | ---: | ---: | ---: | ---: |
| 250 | 0.914 | 65.41% | 0/16 | 1/16 |
| 500 | 0.529 | 81.02% | 0/16 | 7/16 |
| 750 | 0.193 | 94.67% | 0/16 | 14/16 |
| 1000 | 0.0461 | 98.86% | 3/16 | 15/16 |

Начальный loss 5.6726, accuracy 0.58%; целевой набор содержит 3941 токен с EOS. На шаге 1000 остаётся 45 неверных teacher-forced токенов (выведено округлением из Float32 accuracy); лишь 3 последовательности полностью правильны при teacher forcing. Точность EOS на исходных префиксах 100%, но в самостоятельной генерации EOS 15/16. Python синтаксически валиден для 4/16.

**Критерий 16/16 не достигнут.** Обучение уверенно продвинулось: модель способна выучить отдельные целые пары, а оставшиеся ошибки могут портить программу после длинного правильного префикса. Например, программа про высоту мяча совпадает первые 152 из 161 байта, затем ломается `return result`. Высокая token accuracy при правильном префиксе не равна вероятности правильной целой программы: ошибки по позициям зависимы, а после первой ошибки меняется собственный префикс.

Сейчас перепроверены AST и первые расхождения трёх напечатанных неудач: позиции 167, 152 и 108 (нумерация с нуля), все три не разбираются как Python. Остальные программы не доступны по отдельности: в сообщении есть агрегаты, полный JSON и checkpoint не переданы. Программы не исполнялись; функциональное качество и обобщение не проверены. Совпавшее число teacher-forced/greedy exact (3) не доказывает совпадение их IDs или корректность всех масок.

## Скорость и текущие проверки результата

Активное время 0–2250 — **91.83 с**, включая greedy-диагностики и запись checkpoints. Первые 1000 — 42.87 с; продолжение 1250 обновлений — 48.96 с. Это около 24.50 / 25.53 обновления/с соответственно с указанными накладными расходами, не чистый throughput обучения.

В прежнем [опыте на 512 парах](longer-training.md) цикл 2000 обновлений занимал 51.45 с, включая periodic validation loss, но без greedy/checkpoint внутри цикла: около 38.87 обновления/с, 25.73 мс/обновление. При сохранении этой скорости 10 000 обновлений заняли бы около 257 с (4.3 мин); это грубая экстраполяция, не измерение большого корпуса. Длины/подготовка batch и диагностики могут изменить время. Ускорение обучения пока не является приоритетом.

Отдельного таймера greedy в текущем опыте нет, поэтому новую скорость инференса не устанавливаем. Последний прежний test-замер: 896/1919 за 184.12 с, **4.87 ответа/с**; для 180 с требуется **10.66 ответа/с**. При прежней нагрузке это около 2.19 раза быстрее, полный test на такой скорости дал бы около 394 с (экстраполяция, не измеренный полный прогон). Это результат другой модели после обучения на 512 парах, а не текущих весов после запоминания 16.

По коду сохраняются byte-последовательности, FP32 и полный пересчёт decoder-префикса без KV-кеша. При teacher forcing все целевые позиции обрабатываются параллельно; при greedy выполняется последовательный decoder вызов для каждого нового токена. Батч не сокращается после EOS отдельных строк и идёт до самого длинного ответа: у текущих 16 — до 498 шагов. Поэтому средняя длина 246 сама по себе не доказывает двукратное ускорение. Вклад каждого фактора сейчас не профилирован.

Сейчас без повторного обучения проверены совпадение кода, порядок, отсутствие errors, непрерывность логов и остановка на 2250; восстановлены hash/длины набора из уже скачанного разрешённого shard. Перепроверены текст/AST и первые расхождения трёх примеров на шаге 1000 и точный текст/AST трёх финальных примеров. Полные 16 генераций по отдельности, JSON и checkpoint не переданы, поэтому остальные 13 подтверждаются сохранёнными агрегатами. GPU-цифры получены пользователем; агент сейчас обучение/генерацию/программы не запускал.
