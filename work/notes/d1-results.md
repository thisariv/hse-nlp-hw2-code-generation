# D1: результаты диагностики train-reference

**A/B не использовать для удаления:** среди886 кандидатов со строгой модой
дублей модели совпали с модой лишь в121 случае — **13,66%**. Повышение CE
ухудшает этот прокси. Лучший из проверенных фильтров — строгий **C**,121 строка;
его100% согласия с модой задано самим правилом и не доказывает реальную точность.
Для основного [R1](r1-plan.md) рекомендую train **без D1-удалений**, сохранив protected
exclusion. Готовы обычный и long2x orders и для C, и для такого контроля.

## Главная оценка точности: строгая мода дублей

Join по исходным compact ids с seed из полной переписи [clean-cooldown-analysis](clean-cooldown-analysis.md).
Строгая мода здесь: группа≥3, единственный ответ с частотой≥2/3 после cache
exclusions; исходные ответы кластеризованы прежним anchored `isclose`.
Для кандидатов A с такой модой считаем совпадение **обоих модельных ответов с модой**.
Это условный прокси правильности: мода сама может быть ошибочной.

| Отбор кандидатов | Всего удалили бы | Есть строгая мода | Модели = мода | Прокси точности |
|---|---:|---:|---:|---:|
| A; исходный B top2% |38 644|886|121|**13,66%**|
| A + top1% CE/bin |27 914|728|79|10,85%|
| A + top0,5% CE/bin |14 133|508|39|7,68%|
| A + top0,1% CE/bin |2858|206|8|3,88%|
| A + CE≥1 |6236|357|16|4,48%|
| A + CE≥1,5 |673|102|4|3,92%|
| A + CE≥2 |100|9|0|0/9|
| C: A + обе модели = строгая мода |121|121|121|100% **по определению**|

В886 A-кандидатах **753 reference совпадают с модой**,121 модельная пара
совпадает с модой,12 — ни reference, ни модели. Всего393 разных вопроса;
95% bootstrap по группам (2000 draws, seed2026101503) для13,66% даёт
**[11,22%;16,31%]**. Это неопределённость условного proxy, не CI истинной точности
на всех38 644 строках. Строки дублей зависимы; обычный row-Wilson в JSON — лишь справочный.

По compact bins точность A: **94/715=13,15%;12/103=11,65%;11/44=25,00%;4/24=16,67%**.
Повышение CE не делает согласие двух коррелированных моделей надёжнее:
likelihood конкретной программы не является проверкой математики.

Границы B top0,5% по bins:0,90088/0,79248/0,73730/0,78320;
top1%:0,77246/0,69727/0,64795/0,68408; top2%:0,65430/0,60205/0,55908/0,58789.
Исходные A и B top2% **эмпирически совпали**, поскольку greedy ограничен
верхними≈1,39% каждого bin. Более строгие пороги выше — диагностические,
не настроены по heldout/test.

## Ручная проверка

[Все30 вопросов, reference-код, код обеих моделей, ответы и вердикты](d1-manual-review.md).
Простая случайная выборка A без возвращения, seed2026101501; выбор до чтения условий.
Модельный код получен CPU FP32 replay pinned weights на frozen D1 decoder;
**все60 ответов совпали с D1**, все30 reference переисполнены и совпали.

- **14/30 (46,7%)** reference ошибочны по принятому разбору; консервативно
  без неоднозначного «exchanges» в №3 — **13/30 (43,3%)**.
- Модели правы в9/30 (30,0%), консервативно8/30; в ещё5 случаях reference
  неверен, но модельный ответ также неверен или не следует из буквального условия.
- В4 случаях reference прав, ещё1 — корректная формула с округлением;
  в9 условие неполно/противоречиво, ещё2 неоднозначны. Эти11 не записаны
  в подтверждённые ошибки reference.

Это **прокси одного разбора**, без независимого adjudication. Для масштаба
row-Wilson95 для14/30≈[30,2%;63,9%], он не учитывает субъективность вердиктов.
Различие с13,66% на дублях ожидаемо: строгая мода есть лишь у886/38 644=2,29%
A, это другая популяция. Нельзя объединять оценки или переносить их на весь train.
В ручной выборке нет кандидатов C: реальная точность C ею не измерена.

## Правила и покрытие

| Правило | Удалений train-пар | Решение |
|---|---:|---|
| A |38 644 =0,3973% train|Отклонить: много совместных модельных ошибок|
| B: A + top2% CE/bin |38 644|Отклонить; сейчас совпадает с A. Более высокие CE ухудшают proxy|
| C: A + совпадение со строгой модой |121 =0,001244% train|Лучшее консервативное правило; неизвестная мода → строку оставить|

C здесь требует **положительного подтверждения** модой. «Сохранить все singleton A,
отсеяв лишь известные противоречия с модой» не является этим правилом: для
основной массы строк оно оставило бы ненадёжный A. C из исходного анализатора
формально включает B, но на имеющемся subset совпадает с указанным C без CE.

**Полную долю вероятных ошибок train, найденную D1, оценить нельзя:** нет
случайного greedy-контроля вне high-CE хвоста. 34,8% pool или1,39% train не равны recall.
Можно дать проверяемый train-only proxy: во всём кеше **11 287** строк вне
строгой моды. Greedy охватил190 (1,6834%), C подтвердил121 — **1,0721%**
всего известного строгого меньшинства; среди190 подтверждены63,68%.
Оставшиеся11 097 таких строк вообще не сгенерированы. Это поддерживает вывод,
что отбор только по самому высокому CE имеет слабое покрытие ошибок reference.

Во всём top4% CE лежат примерно546 строк строгого меньшинства, top10% —1434,
top20% —2918, top50% —7029 (включены FP16 ties на quantile boundary).
Даже полный pool top4% может покрыть лишь≈4,84% этого proxy; потерянные ошибки
распределены далеко за high-CE хвостом. Singleton-шум этим расчётом не измерен.

## Рекомендация R1 и расширение после17.10

1. **Основной R1 — без A/B и без D1-удалений.** C сохраняем готовым резервом:
   убрать121/9,7M строк допустимо как консервативный опыт, но измеримого улучшения
   не ожидаю. Полное перемешивание order меняет значительно больше предъявлений,
   чем сами121 удаления; нельзя приписывать разницу только чистоте данных.
   Для protected-safe контроля использовать готовый `r1-control` через
   `data=filtered`; это технический режим загрузки, D1-кандидаты там не удалены.
2. **Не тратить перед R1 квоту на greedy большей части train.** По фактическим
   phase timers более медленная модель дала143,61 rows/s, вторая167,09;
   это paired pipeline на двух T4 одновременно. CE уже полный, повторять его не нужно.
3. Если проверять более широкую фильтрацию, сначала сгенерировать **11 097
   непроверенных strict-minority rows**, затем случайный низко/средне-CE контроль.
   Decode-сценарий≈1,3мин для11 097, практический бюджет **10–20мин** с setup,
   SHA, хвостами и сохранением. Это гораздо полезнее для C, чем ещё один проход
   только high-loss. Full random audit нужен отдельно, чтобы оценивать общий шум.

| Расширение парного greedy | Новых строк | По фактической скорости | С safety1,6 +10мин setup |
|---|---:|---:|---:|
| Закончить top4% |253 705|29,4мин|57,1мин|
| До top10% |837 250|1,62ч|2,76ч|
| До top20% |1 809 823|3,50ч|5,77ч|
| Остальной train |9 590 413|18,55ч|29,85ч|

Это **сценарии**, не замеры будущего запуска: lower-CE программы могут быть
короче/быстрее, outliers и CPU/SymPy меняют скорость. Full train не помещается
в один12-часовой paired T4×2 run даже по точечной оценке; понадобится разбивка,
resume, компактный output и сохранение model code хотя бы для аудита.
Никакие новые GPU/API runs в этой CPU-сессии не запускались, данные не публиковались.

Коммит **не создан**: попытка `git add` перечисленных D1/R1-integration paths
получила exit128 — песочница запретила создание shared worktree `index.lock`
(`Operation not permitted`). Индекс не изменён, обходов ограничения не было;
все файлы сохранены. [Git receipt](../checks/d1-results-git.json).
