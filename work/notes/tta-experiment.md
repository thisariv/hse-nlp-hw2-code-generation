# TTA: голосование по равнозначным формам вопроса

## Гипотеза и исходная точка

Собственная гипотеза: детерминированная смена поверхностной формы вопроса уменьшит корреляцию ошибок samples сильнее, чем повредит отдельному sample. При неизменном количестве samples голосование станет точнее. [V8](final-inference.md#v8-c-long2x--p1-b--w-plain-b4) public 78,54%, v9 78,44% — факты со слов пользователя; свежий GPU-tune обеих 1532/2048. Старые K8-максимумы1541/1547 не являются свежим контролем. Сравниваем только ветки нового общего пула.

Мотивация из Li et al. (2023): варьировать prompt наряду с sampling. Здесь нет few-shot examples, learned verifier, внешних данных, моделей или парафразеров; это собственная проверка узкого правила TTA, а не воспроизведение DiVeRSe. Обучение не меняется; данные только `SlavaYus/tinysms_qa_12m`.

Вход BPE8k без нормализации чисел: pretokenizer изолирует **каждую цифру** (`\p{N}`), затем ByteLevel без regex; PAD/BOS/EOS0/1/2 и offset3. Вопрос: BOS + encode(question) + EOS. Compact30 относится только к выходному коду. Замена разделителя, `$`/слова или нулей меняет последовательность токенов, хотя числовая величина сохраняется.

Выбраны три идемпотентных правила, каждый применяется к исходному вопросу отдельно:

| Правило | Пример | Train изменено | Tune2048 | Eval2048 |
|---|---|---:|---:|---:|
| `dollar-words` |`$5 each → 5 dollars each`|23905 (19,921%)|462 (22,559%)|456 (22,266%)|
| `ungroup` |`12,000 units? → 12000 units?`|2198 (1,832%)|49 (2,393%)|49 (2,393%)|
| `price-trim` |`$1.50 each → $1.5 each`; `$5.00 each → $5 each`|3386 (2,822%)|70 (3,418%)|58 (2,832%)|

Ограничения шаблонов намеренно консервативны: не трогаем `$5k`, `$5 million`, `$5-billion`, `$5 dollars`, malformed grouping, невалютные дроби/даты. Некоторые суммы у конца предложения не совпадают с шаблоном. Перевод в `dollars` существенно реже `$` в train, но реально встречается сотни раз; это самый рискованный сдвиг. Наличие обеих форм в корпусе не доказывает равенства условных распределений. Два числовых правила имеют малое покрытие, поэтому общий эффект может быть слабым. Пробелы у пунктуации отвергнуты из-за почти нулевого покрытия; percent-words ещё реже dollars и не выбраны.

Обязательный guard: мультимножество всех числовых значений (`Decimal`, корректные запятые тысяч удаляются) до/после совпадает. Проверены все120000train и4096heldout вопросов для каждого правила; идемпотентность также проверена. Само равенство чисел недостаточно для семантической эквивалентности; её обеспечивают узкие шаблоны неизменной валюты/единиц. [Unit-тесты](../kaggle/tta_tests.py) проверяют суммы, границы, исключения, неизменность вне шаблона. [CPU pipeline](../checks/tta-pipeline.json) действительно исполняет embedded worker, стандартную и QK-модели и executor на tiny fixture со всеми ветками/K8.

### Политики, выбор и независимое подтверждение

Greedy anchor **всегда исходный вход**, в тройке — C-long2x. Замороженный count→greedy→meanLP→order и graph-isclose1e−6 из v8; gold не участвует в выборе голоса. Неуспешное исполнение остаётся sample и в бюджете.

Смешанная политика для упорядоченного подмножества правил: слоты0,2,4,… берутся с исходного входа; слоты1,3,5,… по кругу с правил подмножества. Если правило неприменимо, слот берётся из исходного пула. У каждого пула свой счётчик; всегда берётся первый ещё не использованный sample. Никакого повтора одного исходного sample при fallback. На каждом вопросе ровно столько же samples, сколько у контроля. Правила не композируются в одном входе.

Предобъявленный порядок7смесей: words; ungroup; trim; words+ungroup; words+trim; ungroup+trim; words+ungroup+trim. Порядок правил внутри соответствует таблице.

- Single-model: для каждой модели K4 иK8, без дополнительного greedy-голоса; исходный greedy только для tie, как в [b4-results — K8 tune2048 и ансамбли](b4-results.md#k8-tune2048-и-ансамбли). Все7смесей — вторичный анализ.
- **Первичная метрика/выбор:** v8-подобная тройка C-long2x/P1-B/W, K1=1/1/1→K2=1/8/1, original C greedy. Смешивание применяется к slots каждой модели отдельно. Первый sample исходный, поэтому stage1/early-stop и per-question budget **совпадают с контролем побитно**. Меняются только дополнительные samples P1-B. Выбирается смесь с максимумом tune matches; ничья — раньше в указанном списке. Без перебора новых K/моделей/правил после результата.
- Greedy/per-sample accuracy каждого варианта против original: все2048 с fallback и отдельно применимые задачи. Сдвиг — парная разница долей; для samples средняя correctness поK8 на задачу.
- Корреляция ошибок: Pearson binary error по применимым задачам, средняя всех28пар original-original и64пар original-variant; дополнительно полная выборка с fallback. Константные пары пропускаются с явным счётчиком. Это описательная корреляция, не причинная оценка.
- CI: парный bootstrap по задачам, **20000реплик, seed2026101902**, percentile95%; все samples одного вопроса ресэмплируются вместе. Tune-интервалы описательные после выбора из7смесей. Победитель tune фиксируется в отдельном JSON **до чтения eval accuracy**, затем ровно он подтверждается на eval2048.
- Успех: eval Δ≥**+0,4п.п.** и нижняя граница парного95%CI>0 при том же per-question sample budget. При успехе — набросок v10 с теми же моделями/бюджетом, выбранным распределением входов и прогнозом≤140с; иначе сохранить v8. Это один заранее выбранный тест на независимом eval, без подбора политики на eval.
