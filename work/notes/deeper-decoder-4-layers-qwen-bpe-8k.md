## Гипотеза и предыдущая база

[19](qwen-style-bpe-8k-swiglu-500k-pairs.md) изменил tokenizer, но число Transformer-слоёв осталось2+2. При100k updates:136/888 reference agreements, byte NLL0.254696 и3/23 правильных вручную; [18](swiglu-500k-continue-to-100k.md) даёт142/888,0.251605 и6/23. Есть ошибки операций при наличии нужных чисел; причиной не доказана именно нехватка ёмкости.

Проверяем **только decoder2→4** на BPE8k. Больше последовательных преобразований признаков префикса и обращений к encoder может помочь строить вычислительную программу. Encoder, ширина, LR и данные сохраняются. Глубина не гарантирует исправления числа или операции; одного seed недостаточно для устойчивого вывода.

## Формализация и бюджет

$$H_j=\operatorname{DecoderLayer}_j(H_{j-1},E),\qquad j=1,\ldots,4.$$

$E$ — итоговый выход encoder, общий для всех decoder-слоёв; $H_0$ — эмбеддинги сдвинутого префикса с позициями. Каждый $j$ имеет свои веса masked self-attention, cross-attention, Pre-LN и SwiGLU FFN. Размер признаков остаётся256; повторение слоя не означает общих весов. После $H_4$ остаются final LayerNorm и отдельный vocabulary head.

Один decoder-layer содержит1 051 728 параметров. Два новых слоя добавляют2 103 456: **8 407 360→10 510 816**. Бюджет подтверждён созданной полной CPU-моделью, а не только оценён по формам.

| Параметр |19 |20 |
| --- | --- | --- |
| Encoder / decoder |2 /2 |2 /4 |
| Ширина / heads |256 /4 |То же |
| FFN |SwiGLU680, biases |То же |
| Norm / позиции |Pre-LN + final LayerNorm / learned2048 |То же |
| Vocabulary |Qwen-style own BPE8192 |То же; hash19 обязателен |
| Embedding / head |Shared source-target embedding, untied head |То же |
| Train / optimizer |500k / FP32, AdamW, batch8, clip1 |То же |
| LR |Warmup1000→0.001, cosine50k→0.0001, floor до100k |То же |
| Updates / inference |100k / KV, batch32, cap512 |То же |

Обучение с нуля: checkpoint19 не загружается. Одинаковый seed42 не сохраняет идентичные начальные общие attention/head-веса после изменения глубины: меняется расход Torch RNG. Инициализатор и рецепт SwiGLU прежние. Python sampling/RNG-порядок, данные и оценки сохраняются.

## Следующий кандидат: encoder2→4, decoder4

Пользователь предложил4+4 и отложил LR. Равная глубина encoder/decoder не требуется архитектурой; проверяем **более глубокое представление вопроса**, а не баланс ради одинаковых чисел. Encoder получает ещё два слоя self-attention+SwiGLU FFN; decoder4 и его cross-attention остаются прежними. Нет доказательства, что именно encoder мешает понимать числа/отношения.

По tensor shapes20 encoder-layer788048 params; ещё2 дают**12 086 912** вместо10 510 816 (+1 576 096). Этот бюджет реализован в [21: encoder4/decoder4](deeper-encoder-4-layers-decoder-4-qwen-bpe-8k.md) и подтверждён созданием модели/короткимCPU-прогоном; T4-результат21 получен: reference178/888,дополнительныйручной19/74,CE.7758,test74.70с;см.разбор21. Encoder вычисляется один раз на входной батч при greedy, decoder работает для каждого выходного токена; ожидается другой профиль стоимости, но время нужно измерить.

Предлагаемый протокол: с нуля, encoder4/decoder4/d256/Qwen BPE8k/500k/FP32/cache/batch8/100k updates и прежний LR. Никаких одновременных изменений batch/width/LR/tokenizer. Непосредственный контроль20,19 дляdecoder-depth и18 длякачества;50k/75k/100k старыйheldout1024/888/ручной74/парные изменения/byte NLL/EOS/имена/AST. Свежий1024 оставить финальному сравнению; fulltest≤180с иtrain timer измерять заново. Новая глубина меняет RNG расход и общие начальные веса; один seed, не доказанный optimum.

Batch size действительно не исследован как фактор качества:16 сравнивал online/cache/AMP приbatch8. Позже можно отдельно проверить16/32 по полезным tokens/s/памяти/качеству.100k updates приbatch8 дают800k предъявлений, при32 —3.2M: это уже больший data budget. При фиксированных800k предъявлениях batch32 получает25k updates вместо100k, поэтому бюджет/горизонтLR надо явно задавать. Не повышать LR автоматически или менять batch одновременно сencoder; полезный размер зависит от gradient noise и имеет убывающую отдачу ([McCandlish et al.](https://arxiv.org/abs/1812.06162)).
