3141/4096 против3133, Δ+0,195п.п., парный95%CI[−0,244; +0,635]п.п.

### Гипотезы и закрытая сетка

Больше голосов может исправить неустойчивые ошибки; третий этап направляет
их на строки с рассеянными ответами. T1.0 может увеличить разнообразие
ценой точности отдельных samples. Это собственные гипотезы.

Сохраняются модели/SHA E1, greedy C, production numeric connected-components
isclose1e-6/count/greedy/meanLP/stable order, код greedy внутри выигравшей
компоненты. Stage1: greedy плюс первые T0.7 samples C/P/W; при численном
единогласии всех четырёх — остановка. Неуспех исполнения расходует голос
и бюджет. Ни gold, ни correctness не участвуют в предсказании/остановке.

Полный декартов список фиксируется до анализа, без последующего расширения:

|Семейство|Варианты|
|---|---|
|Контроль|v11, C/P/W=1/8/8, только T0.7|
|Бюджет и температуры|C∈{1,2,3,4}; P=W∈{8,12,16}; температурный шаблон P/W∈{только0.7, каждый4-й slot1.0, каждый2-й slot1.0}|
|Третий этап и комбинации|C∈{1,2,3,4}; P=W=8; те же3температурных шаблона; порог доли победителя q∈{0.5,0.6,0.7}; дополнительные(P,W)∈{(4,0),(0,4),(4,4),(8,0),(0,8),(8,8)}|

C во всех вариантах T0.7; K_C включает первый stochastic sample,
greedy — отдельный голос. Температурный slot нумеруется с1; первый всегда
T0.7. Используются сохранённые prefix каждого температурного пула,
без перестановок/повторного использования sample. Stage3 продолжает
температурный шаблон после slot8; максимум16stochastic на P/W.
В вариантах C>1 дополнительные C берутся при неединогласии stage1 до
решения о stage3. Это заранее заданные комбинации семейств.

Stage3 вызывается только после неединогласного stage1 и завершения stage2,
если размер выигравшей numeric-компоненты / число **всех** голосов
(greedy, включая нечисловые неуспехи в знаменателе) строго меньше q.
Если numeric-компонент нет, доля0. После расширения — то же голосование.
Контроль совпадает с вариантом C1/P8/W8/T0.7; дубликат исключается.
Итого36base+216stage3=252политики, включая контроль.

### Выбор и время

Выбор на объединении E1 tune2048+eval2048,4096строк: **одна primary**
с максимальным числом верных ответов среди прогнозов≤150с.
Ничья: меньше прогноз, затем лексикографическое имя. Контроль допустим;
если победил контроль, улучшение не заявляется. Лучшие по семействам
и прочие CI — только описательные результаты после подбора.
До фазы2 сохранить JSON выбора и отдельную квитанцию SHA256,
SHA предрегистрации/политик/анализатора/журналов/timing.

Прогноз на1919строках: реальные фазы v11 сохраняются раздельно.
Greedy и stage1 неизменны; фиксированная часть — полный126,846266345с
минус stage2_sampling_restore_submit56,089473971с.
Stage2 и stage3: E1 seconds/sequence по модели и температуре
(T0.7 extras:K15; T1.0:K8), средние использованные дополнительные
голоса на всех4096строках ×1919. Общий множитель калибруется так,
чтобы контроль на том же E1-пуле восстанавливал stage2 v11 точно.
Одинаковый множитель для всех вариантов. Для stage3 дополнительно
начисляется полный stage1_decision_wait v11=2,06896138с как цена
второго барьера исполнения. Прогноз — перенос throughput, не cold test;
новые K нужно реализовать с ограничением lanes и прежним OOM rollback.

### Подтверждение

Один свежий GPU-пул: greedy C/P/W; K16 T0.7 (1+15), K8 T1.0,
исполнение; без токенного ансамбля, soups и crossLL. Ровно75кандидатов
на строку; тот же формат pools/candidates/manifest E1. Только primary
против контроля; без нового выбора по результатам фазы2.

Парный percentile bootstrap по задачам20000реплик, seed2026102002,
95%CI, gains/losses. Успех: Δ≥+0,3п.п., нижняя границаCI>0,
замороженный прогноз≤150с. CI по задачам не оценивает вариативность
повторной генерации. До успеха сохранитьv11.

**Обнаруженное пересечение:** E1 уже использовал именно heldout4k.json,
SHA `28a3c0c9088c5b4a17d75d216e4abc4262cc9ca62884966c43e7ec09b6f040c2`.
fixed_split делит все его4096строк на tune/eval. Утверждение о нетронутом
heldout4k не подтверждается исходниками и журналами.
Свежий sampling на тех же задачах проверяет повторяемость sampling,
но не является независимым holdout по задачам.

**Уточнение при возобновлении:** только аккаунт thisarivson, дефолтный
SDK/CLI-конфиг; значения credentials не читаются и не выводятся.
аккаунт друга не используется ни для операций, ни как источник datasets.
аккаунт друга — только чтение pinned output B6v1. B6 FP16 перенесены в новый
private `thisarivson/nlp-hw02-b6-fp16`, P1-B берётся из уже существующего
`thisarivson/nlp-hw02-p1-weights`. Обратные SHA проверены, временные веса удалены.
Квитанция `e2-friend2-inputs.json` относится к ранней прерванной
попытке до смены инструкции; этот источник в текущем запуске не использован.
Ровно один push с durable ledger до запроса, exact code/version/private
parity. QUEUED>10мин или RUNNING>12мин без output — зафиксировать,
ждать до60мин без собственного перезапуска/отмены/удаления.
Последняя внешняя версия принимается только с exact code parity.
Notebook Run All выполняет тот же протокол без API/credentials внутри.
