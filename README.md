# Генерация кода маленьким Transformer'ом

ДЗ2 курса «Глубинное обучение для обработки текстов» (НИУ ВШЭ, 2026). По английскому условию школьной математической задачи модель пишет Python-функцию `solve()`; бот курса исполняет её и сравнивает число с ответом. Модель — encoder–decoder Transformer, обученный с нуля только на [SlavaYus/tinysms_qa_12m](https://huggingface.co/datasets/SlavaYus/tinysms_qa_12m). Ответы на все 1919 тестовых вопросов нужно сгенерировать не дольше чем за 180 секунд на одной NVIDIA T4.

**Результат:** 80,10% на public-лидерборде. Финальный ноутбук: test за 122,7 с на T4, пик памяти 11,1 ГБ, на отложенной выборке tune — 1560 из 2048 (76,2%).

## Решение в двух словах

- **Три модели по 6+6 слоёв:** W (ширина 768, QK-нормировка, ≈99 млн параметров), C-long2x (ширина 512, ≈54 млн, длинные программы предъявлялись дважды) и P1-B (ветка C с усечением самых трудных примеров на охлаждении).
- **Данные:** 9,7 млн отфильтрованных пар, компактное обратимое представление кода (на 21% меньше токенов), собственный BPE на 8195 токенов.
- **Обучение:** AdamW, FP16, расписание warmup → постоянный LR → длинное охлаждение `1−√`. Длинное охлаждение дало около +1,5 п.п. каждой модели.
- **Инференс:** greedy-ответ W и по одному сэмплу каждой модели. Если все четыре программы вернули одно число (≈62% задач) — ответ готов. Иначе ещё по 7 сэмплов C и P1-B и голосование по результату исполнения.
- **Быстрый декодер:** KV-кеш, уплотнение батча по мере завершения строк, асинхронная проверка конца, исполнение программ на CPU параллельно с генерацией на GPU.

Подробно, со всеми экспериментами и выводами, — в [отчёте](report.pdf).

## Быстрый запуск

**Kaggle:** импортировать [submission/inference.ipynb](submission/inference.ipynb) → Add Input → датасет `thisarivson/nlp-hw02-final-weights` (версия 4) → GPU T4 → Run All. Ответы появятся в `/kaggle/working/final-package-v2/answers.jsonl`.

**Colab:** runtime с T4, перед Run All выполнить отдельную ячейку (токен Kaggle не нужен):

```python
!pip install -q kagglehub tokenizers sympy numpy
import os, kagglehub
root = kagglehub.dataset_download("thisarivson/nlp-hw02-final-weights/versions/4")
os.environ["HW2_WEIGHTS_ROOT"] = root
os.environ["HW2_CODE_ROOT"] = os.path.join(root, "code")
os.environ["HW2_OUTPUT"] = "/content/hw2-output"
```

Метод сэмплирует кандидатов, поэтому повторные прогоны дают немного разные ответы: два прогона одной и той же конфигурации получили на public 80,10% и 79,37%.

## Примечания

- Работа велась вместе с агентами (Claude Code и Codex): заметки, журналы и квитанции писались по ходу работы и местами очень сжаты. Связный рассказ и описание работы с агентами — в отчёте.
- Kaggle-запуски шли на трёх аккаунтах: моём (`thisarivson`) и двух аккаунтах друзей, в коде они обозначены `friend1` и `friend2`. Ссылки на Kaggle-ноутбуки в заметках ведут на приватные запуски, но их код сохранён в `work/kaggle/notebooks/`: каждый ноутбук несёт внутри исходники своих модулей.
- Перед публикацией ники аккаунтов и локальные пути заменены, поэтому SHA части исторических файлов в `work/checks/` могут не совпадать с текущими байтами. Код финального пакета `submission/code/hw2_codegen/` не менялся: он байт-в-байт совпадает с копией в датасете, SHA записаны в `package-manifest.json`.
- Данные, кеши, полные чекпоинты и outputs Kaggle в Git не входят. Веса финальных моделей лежат в датасете.
- Заметки были частью личного Obsidian-хранилища, поэтому ссылки на заметки вне этого задания оставлены обычным текстом.
