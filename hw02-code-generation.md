## Что известно о данных

Вопросы на английском, код Python содержит функцию `solve`; docstring удалён. Несколько программ могут соответствовать одному вопросу. Программы train предварительно не исполнялись и не фильтровались по успешному числовому ответу.

Сейчас локально изучены 20 000 пар из четырёх фиксированных train-файлов и все 1919 test-вопросов. Средняя программа занимает 237.39 байтовых токена с EOS, p95 — 442; все 20 000 программ синтаксически разбираются. Исполнение и функциональная корректность не проверялись. Полный корпус не изучен; общие число строк и описание качества остаются сведениями авторов. [Метод выборки, длины и бюджет](work/notes/first-baseline.md).

## Задача модели

Обычная условная авторегрессионная генерация:

$$
p_\theta(c\mid q)=\prod_{t=1}^{T}p_\theta(c_t\mid q,c_{<t}).
$$

$q$ — вопрос, $c=(c_1,\ldots,c_T)$ — токены программы с EOS, $\theta$ — обучаемые веса. Энкодер представляет вопрос; декодер предсказывает следующий токен кода, учитывая вопрос и предыдущий код. При обучении префикс берётся из исходной программы, при генерации — из собственного ответа модели.

В обычной интерпретации pass@1 оценивает успех одной программы на задачу, то есть её функциональную корректность. Точный checker курса в условии не описан. Для локальной проверки нельзя автоматически считать совпадение с эталонным текстом полноценным pass@1.

## Предлагаемый план

Это наш рабочий план, а не дополнительные требования курса. Простой байтовый baseline → более долгий запуск → успешное запоминание 16 пар → 20 000 пар / 10 000 шагов → продолжение до 50 000 выполнены. На последнем варианте форма программы улучшилась, семантика слабая. Опыт 07 с KV-кешем завершён: на T4 6.03×, test 61.40 с, ответы прежние. Приоритет возвращён качеству/функциональной проверке; следующий обучающий фактор — обратимый BPE на разрешённом train, затем ёмкость/данные по результатам. [Очередь и правила сравнения](work/notes/experiment-plan.md). [Результат 07 и текущие ограничения](work/notes/kv-cache-inference.md).

1. **Зафиксировать проверку и вычислительный бюджет.** Уточнить формат файла бота, правила вызова `solve`, сравнения численных результатов и границы таймера. Проверить доступную GPU, память и время одной сессии. До этого не выбирать окончательный размер модели.
2. **Изучить ограниченную часть train.** Посмотреть длины вопросов/кода, повторяющиеся вопросы, синтаксис, отступы и необычные программы. Выделить воспроизводимую validation по целым вопросам, исключив все их варианты из обучающей части. Test оставить для финальной генерации. Не исправлять программы с помощью внешних моделей и не создавать новые обучающие таргеты.
3. **Подготовить токенизацию и маленькую модель.** Согласованный первый вариант: UTF-8-байты без обучения токенизатора; `nn.Transformer` с 2+2 слоями, шириной 128, обычным FFN, Post-LN и обучаемыми позициями. BPE и Pre-LN оставить для отдельных последующих опытов. Случайная инициализация всех весов. Проверить round-trip токенизатора, сдвиг target, BOS/EOS/PAD и causal/padding masks. На нескольких парах проверить способность переобучиться; это короткая проверка корректности, не эксперимент качества.
4. **Измерить рабочий цикл и выбрать ускорение.** На готовых весах проверить KV-кеш, затем по одному исключение finished rows, FP16 и batch. Перед более дорогим обучением измерить время batch, непустые токены/секунду, padding и GPU-память; отдельно проверить предварительную токенизацию, bucketing, AMP FP16 и batch. Backend attention проверять на реальной T4. Accumulation добавлять при необходимости по памяти.
5. **Получить первый baseline.** Teacher forcing, token cross-entropy без PAD; сначала AdamW и clipping. Для первого пробного запуска — 200 обновлений и greedy decoding; warm-up проверять отдельно при необходимости. Затем увеличивать обучение до осмысленной генерации. Записывать validation loss, синтаксическую корректность, функциональную метрику по согласованной процедуре и ошибки. Если локальная проверка сравнивает исполнения с исходными программами train, считать её proxy: сами эти программы могут ошибаться. Результаты исполнения использовать только для оценки, не как новые таргеты обучения.
6. **Рано проверить 180 секунд.** На одной T4 измерить генерацию всех 1919 test-вопросов без обращения к скрытым ответам. Сохранить исходный порядок. По одному проверить batching, длину генерации, остановку по EOS и KV-кеш; для cross-attention можно кешировать проекции энкодера. Отдельно фиксировать подготовку, токенизацию, GPU-генерацию и сохранение. Конкретный выигрыш каждого ускорения установить замером; иметь запас до 180 секунд.
7. **Улучшать качество короткими опытами.** По ошибкам выбрать небольшое число гипотез: learning rate; размер/состав разрешённой train-части; ширина или глубина; токенизация; greedy против небольшого beam. Менять один фактор, сохранять остальные условия и бюджет. При смене архитектуры/токенизации переобучать сравниваемый вариант. Beam оставить только при полезном приросте pass@1 и соблюдении лимита. Конфигурацию выбирать по сочетанию качества и времени, а не по одному loss.
8. **Финальный запуск и сдача.** Обучить выбранный вариант за заранее оценённое время; сохранить лучший checkpoint по validation. В новой Colab/Kaggle-сессии на одной T4 проверить notebook, порядок/число ответов, формат файла и полный замер. Собрать весь код и PDF-отчёт: baseline, все опыты, выводы, итоговое качество/время, использование агентов. Отправку в бот выполнять отдельно по запросу пользователя.

Итог каждого опыта сохранять в `work/`: гипотеза → единственное изменение → данные/seed/бюджет → loss и функциональная метрика → время/память → вывод. Сдачу готовить в `submission/`; данные и checkpoints не коммитить.

## Что пока требует уточнения

- Условие указывает бот, но не схему файла, точный checker, численную толерантность, квоты посылок и состав 180-секундного замера. Боту сообщения не отправлялись.
- В формуле рейтинговых баллов для 10-го места из 10 получается $8(1-9/10)=0.8$, а в примере написано 0.5. Пример и формула расходятся; окончательный расчёт надо сверить с преподавателями.
- Пользователь подтвердил T4 в Colab; длительность сессии не гарантирована. Последний saved полный1919 test15 —36.64с при FP32/KV/batch32; обучение100k —36.03мин. NativeBF16 TensorCore math наT4 отсутствует; AMP FP16/профиль обучения ещё не проверялись. Схема официального checker/таймера остаётся открытой.
